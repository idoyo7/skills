# /freeze — 얼음! 세션 예약, 땡에 자동 재개

한도에 걸렸거나 걸리기 직전일 때 부른다. 지금 세션의 작업 상태를 얼려두고, 땡(리셋 시각)에 스크립트가 재개한다.

```
얼음 ─▶ 백그라운드 중지 ─▶ handoff/원장 작성(유일한 LLM 작업) ─▶ reserve/arm(슬리퍼 기동) ─▶ 세션 종료
땡  ─▶ 슬리퍼 기상 ─▶ haiku 프로브(한도 확인) ─▶ 재개(resume 또는 ledger) ─▶ 결과 기록
```

경로 변수:

```bash
FZ=~/.claude/skills/freeze/scripts
```

## 두 가지 축이 있다 — 언제 거느냐(무장 시점), 무엇을 넘겨받느냐(재개 방식)

이 둘은 서로 다른 질문이고 독립적으로 고른다.

### 1. 언제 거느냐 — 얼음 vs 무장

| 모드 | 언제 | 명령 |
|---|---|---|
| **얼음** (사후) | 이미 한도에 걸렸거나 지금 멈춰야 할 때 | `reserve --at auto` |
| **무장** (선예약) | 긴 작업을 시작할 때 미리 걸어두고 남은 쿼터를 끝까지 태우고 싶을 때 | `arm` |

무장 모드가 장시간 작업의 기본이다. 한도에 막히는 순간엔 세션이 아무 일도 못 하므로(handoff 를 쓸 토큰조차 없다) **막히기 전에 걸어두는 쪽이 안전하다.**

```
작업 시작 ─▶ arm (땡 예약 + handoff/원장)
             ├─ 계속 진행 … 남은 쿼터 소진
             ├─ 막힘 → 그대로 두면 된다 (슬리퍼 대기 중)
             └─ 먼저 끝남 → done (예약이 재개 없이 종료)
                        땡 ─▶ 프로브 ─▶ (다음 창 선무장, 못 끝낼 대비) ─▶ 재개
```

체인은 기본 2회(`--chain-left`)다. 이 창 안에 못 끝내면 **재개를 부르기 전에 thaw 자신이** 다음 창을 결정적으로 미리 걸어둔다(한도에 막힌 세션이 스스로 arm 을 걸 토큰이 없을 수 있어서다) — 재개 세션이 직접 arm 을 걸 필요는 없다. 재개 세션이 먼저 끝나면 `done` 으로 알려야 선무장해 둔 다음 창이 헛돌지 않고 조용히 해제된다. 남은 횟수가 0이 되면 체인이 멈춘다 — 무한히 도는 것을 막는 안전장치.

### 2. 무엇을 넘겨받느냐 — resume vs ledger (`--mode`)

| 모드 | 재개 방식 | handoff 에 뭘 적나 | 쓰는 상황 |
|---|---|---|---|
| **resume** (기본) | `claude -p --resume <세션>` — 대화 전체 복원 | **목표와 완료 기준만.** 대화 문맥은 이미 있다. | 창 하나만 넘기는 짧은 공백, 5시간 이내 재개 |
| **ledger** | 대화를 복원하지 않고, 원장 한 장만 실은 신선한 세션 | **원장 자체가 유일한 명세.** 아래 "원장 작성 규칙" 참고 | 여러 창을 이어가는 장시간 작업, 5시간 창을 넘긴 재개 |

**왜 둘로 나뉘는가.** `--resume` 은 세션 캐시가 살아 있을 때(1시간 이내)만 싸다. 5시간 사용량 창이 리셋된 뒤 `--resume` 으로 재개하면 캐시 TTL 이 이미 끝나 있어 30만~60만 토큰짜리 대화 전체를 콜드 리드해야 한다 — 정확히 freeze 가 없애려는 비용이다. ledger 모드는 대화를 아예 복원하지 않고 원장 마크다운 한 장(10k 토큰 이하)만 실은 신선한 세션을 띄워 이 비용을 피한다.

**중요 — resume 과 ledger 는 handoff 를 쓰는 방식이 정반대다.** resume 모드에서는 "`--resume` 이 대화 전체를 복원하므로 무장 시점의 handoff 는 목표와 완료 기준만 적으면 된다"는 전제가 성립한다. **ledger 모드에서는 이 전제가 완전히 무너진다** — 재개 세션은 대화 문맥이 전혀 없고, 원장 파일이 유일한 명세다. ledger 모드로 `arm` 할 거면 목표·완료 기준뿐 아니라 재개 세션이 실제로 이어갈 수 있는 수준의 구체적인 다음 단계까지 원장에 담아야 한다.

**어느 쪽을 고를지.** 창 하나 안에서 끝날 걸로 보이거나 리셋 직후 바로 재개할 상황이면 resume(기본)으로 충분하다. 큰 Workflow 를 여러 창에 걸쳐 돌릴 계획이거나, 체인이 여러 번 이어질 가능성이 있거나, 5시간 넘게 자리를 비울 예정이면 ledger 를 고른다 — `workflow-arm` 훅이 큰 Workflow 실행 전에 강제하는 것도 이 모드다.

## 얼음 절차 — resume 모드 (토큰 최소 — 딱 4단계, 추가 탐색 금지)

**1. 하던 일 세우기.** 실행 중인 백그라운드 태스크·워크플로우가 있으면 중지(TaskStop)하고, 각각 어디까지 갔는지만 짧게 파악한다. 새 작업을 시작하지 않는다.

**2. handoff 작성.** `.omc/handoffs/freeze-{YYYYMMDD-HHMM}.md` 한 장. 형식:

```markdown
# freeze handoff — {한 줄 요약}
## 하던 일
{원래 요청과 전체 목표}
## 완료 지점
{끝난 것들 — 파일 경로·커밋 해시 포함}
## 다음 단계
{재개 후 바로 실행할 순서. 구체적으로 — 재개 세션은 이 목록만 보고 움직인다}
## 검증
{끝났다고 판단하는 기준 — 실행할 테스트·확인 명령}
```

**3. 땡 시각 결정.**
- 사용자가 시각을 줬거나 한도 에러 메시지에 리셋 시각이 보이면 그걸 쓴다 (`HH:MM` 또는 `+2h` 형태).
- 없으면 `auto` — reserve 가 OMC HUD 캐시(statusline payload 의 `rate_limits.five_hour.resets_at`, 정확값)에서 읽고, 캐시가 없으면 transcript 로 5시간 윈도우를 역산한다.
- reserve 가 `땡 시각 추정 실패` 로 죽으면 그때 사용자에게 리셋 시각을 묻는다 (AskUserQuestion).
- `--pad <초>` — auto 로 추정한 시각에는 기본 300(5분)이 자동으로 붙는다(리셋 직후 아직 한도가 안 풀렸을 여유분). `HH:MM`·`+2h`·epoch 처럼 시각을 직접 지정했을 때는 그 시각이 계약이므로 기본 패딩이 붙지 않는다 — 여유가 필요하면 `--pad` 를 직접 줘야 한다.

**4. 예약 + 종료 보고.**

```bash
bash $FZ/freeze.sh reserve --at auto --cwd "$(pwd)" --handoff .omc/handoffs/freeze-....md
```

출력의 `얼음 — job=... 땡=...` 한 줄을 사용자에게 그대로 전하고 **작업을 멈춘다.** 이후 이 세션에서 토큰을 더 쓰지 않는다.

## 무장 절차 — ledger 모드 (장시간/여러 창짜리 작업 시작할 때)

```bash
# 1. 원장 작성 — 목표·완료 기준·재개 절차가 담긴 스켈레톤을 만든다
LEDGER=$(bash $FZ/wfledger.sh init --cwd "$(pwd)" --job myjob --summary "한 줄 요약" \
  --goal "구체적 목표" --done-when "끝났다고 볼 기준")

# 2. 원장의 '## 단계' 를 실제 계획으로 채운다 (원장 파일을 직접 편집)

# 3. 예약 — 남은 쿼터를 끝까지 쓰다가 막히면 체인으로 이어붙인다
bash $FZ/freeze.sh arm --mode ledger --cwd "$(pwd)" --handoff "$LEDGER"

# 4. 큰 Workflow 를 실제로 띄운 직후, 등록해서 재개 세션이 끝난 호출을 건너뛸 수 있게 한다
bash $FZ/wfledger.sh run --ledger "$LEDGER" --run-id wf_...

# 5. 다 끝났으면
bash $FZ/freeze.sh done --handoff "$LEDGER"
```

### 원장 작성 규칙 — 결과 본문을 적지 마라, 경로만 적는다

원장은 작업 규모와 무관하게 10k 토큰 이하로 묶여 있어야 한다. 그러려면:

- **`## 단계`** — 체크박스 목록. 각 단계는 재개 세션이 오해 없이 이어갈 수 있을 만큼 구체적으로 쓴다(resume 모드의 "목표만 적어도 된다"는 여기선 안 통한다).
- **`## 워크플로우 런`** — 결과를 요약해서 적지 말고 `wfledger.sh run` 으로 journal/script **절대경로만** 등록한다. 재개 세션은 `wfledger.sh journal` 로 그 경로를 열어 이미 끝난(result 줄이 있는) agent 호출을 골라낸다.
- **산출물**도 마찬가지 — `wfledger.sh mark --step N --artifact <경로>` 로 파일 경로만 남긴다.
- **`## 재개 결과`** 섹션에 재개 세션이 한 일을 적을 때도 요약은 짧게, 큰 산출물은 별도 파일로 빼고 경로만 링크한다.

### 재개 세션이 처음 할 일 — session 필드 갱신

ledger 모드 재개는 매번 새 세션 UUID 로 뜬다. 원장 헤더의 `session:` 필드는 **원래(한도에 막힌) 세션에 고정**돼 있고, `wfledger.sh run`/`journal`/`link` 는 기본으로 이 필드를 읽어 `~/.claude/projects/<slug>/<session>/...` 경로를 계산한다. 갱신 없이 새 워크플로우를 등록하면 존재하지 않는 옛 세션 디렉토리로 경로가 잡힌다. 그래서 재개 세션은 새 워크플로우를 등록하기 **전에** 반드시 한 번:

```bash
bash $FZ/wfledger.sh set-session --ledger "$LEDGER" --cwd "$(pwd)"
```

를 불러 원장의 `session:` 을 자기 자신으로 갱신해야 한다. (재개 프롬프트 자체가 이걸 지시하지만, 사람이 손으로 ledger 모드를 이어갈 때도 잊지 말 것.)

## workflow-arm 훅과의 관계

`hooks/workflow-arm/` 훅은 예약 없이 큰 Workflow 를 실행하려는 시도를 한 번 막고, `wfledger.sh init` → `freeze.sh arm --mode ledger` 순서를 안내한다. 훅이 막았을 때는 안내 명령을 그대로 따라가면 된다 — 세션당 한 번만 막으므로 예약을 걸지 않고 다시 부르면 통과한다(디버깅용 킬스위치는 `FREEZE_HOOK_OFF=1`).

## 땡 (자동)

슬리퍼(`thaw.sh`)가 알아서 한다: 땡 시각까지 대기 → `claude -p --model haiku "ok"` 프로브로 한도 해제 확인(실패 시 15분 간격 최대 12회) → (체인이면 다음 창을 먼저 선무장) → 재개. resume 모드는 handoff 를 읽고 이어서 작업한 뒤 결과를 handoff 하단 `## 재개 결과` 에 남긴다. ledger 모드는 원장을 읽고 이어서 작업한 뒤 단계 체크박스와 `## 재개 결과` 를 갱신한다.

재개 권한은 기본 `bypassPermissions` 다(사용자 결정, 2026-08-17) — 무인 재개엔 승인자가 없어 `acceptEdits` 로는 Bash 가 전부 거부돼 실작업이 안 되는 것을 E2E 로 확인했다. 민감한 작업이면 예약 시 `--permission-mode acceptEdits` 로 하향할 수 있고, 그 경우 재개 세션은 파일 편집만 가능하다.

## 수동 조작

| 상황 | 명령 |
|---|---|
| 예약 확인 (체인 선무장 실패 경고 포함) | `bash $FZ/freeze.sh status` |
| 사용자가 먼저 돌아와 직접 이어서 하겠다 | `bash $FZ/freeze.sh cancel <job>` 후 handoff/원장 읽고 인라인 진행 |
| 컨테이너 재시작으로 슬리퍼가 죽었다 | `bash $FZ/freeze.sh check` — 시각 지난 예약을 즉시 실행 |
| 땡 시각만 미리 알고 싶다 | `bash $FZ/freeze.sh estimate` |
| 무장해 둔 작업을 다 끝냈다 | `bash $FZ/freeze.sh done --handoff <경로>` (체인 중이면 지금 창 + 선무장된 다음 창 모두에 신호가 간다) |
| ledger 원장의 남은 단계만 보고 싶다 | `bash $FZ/wfledger.sh remaining --ledger <경로>` |

## 한계

- 슬리퍼는 detached 프로세스라 **머신·컨테이너가 재시작되면 죽는다.** 예약 자체는 상태 파일(`~/.local/state/freeze/<job>/`)에 남으니 `check` 로 캐치업한다.
- 헤드리스 재개는 앱 세션 목록에 안 뜬다. 결과는 handoff/원장의 `## 재개 결과` 와 `~/.local/state/freeze/<job>/resume-output.txt` 로 확인.
- 땡 자동 결정은 HUD 캐시(`~/.claude/hud/cache/stdin.*.json`)가 있으면 정확하다. 캐시가 없을 때만 ccusage 식 근사(첫 활동 정시 내림 + 5h)로 폴백하는데 이건 수 시간 어긋날 수 있다 — 프로브 재시도(15분 × 12회)가 이르게 잡힌 오차는 흡수하지만, 늦게 잡히면 그만큼 재개가 늦어진다. 체인 내부 재무장은 이 폴백에 기대지 않는다 — 지금 창의 시작 시각에 5시간을 더해 다음 리셋을 결정적으로 계산한다.
- `done --handoff <경로>` 는 그 경로를 참조하는 활성 예약을 완료 신호 대상으로 찾는다. 경로는 절대 realpath 로 정규화해 비교하므로 reserve/arm 때 상대경로를 썼어도 나중에 절대경로로 `done` 을 불러도(그 반대도) 같은 예약을 찾는다. 대상이 하나도 없으면 stderr 경고와 함께 **비영 종료코드**를 낸다 — 자동 호출자(재개 세션 등)가 이 실패를 감지할 수 있다. 완료 신호는 job 마커뿐 아니라 handoff 로 키잉된 마커로도 남아, `done` 호출 시점에 아직 태어나지 않았던 예약(체인 재무장이 그 사이 죽어 마커를 못 받은 다음 창 등)도 나중에 자기 대기 루프에서 그 신호를 본다. 다만 그 예약 자신의 `created_at` 보다 오래된 신호는 무시하므로, 서로 무관한 두 예약이 우연히 같은 handoff 경로를 쓰더라도 나중에 새로 시작한 쪽까지 옛 신호에 걸려 즉시 취소되지는 않는다 — handoff 파일명은 그래도 되도록 고유하게(기본 분단위 타임스탬프 권장 이름 그대로 쓰면 충분히 드물다).
