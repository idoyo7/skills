# 문서 윤문 지침 (humanize-docs 프로파일)

> 이 지침은 `quick-rules.md`와 충돌할 경우 **항상 이 지침이 이긴다.**
> 아래 본문은 마크다운 문서에서 **산문만 뽑아낸 것**이다. 칼럼·에세이가 아니다.
> 정책은 하나다 — **장식만 제거하고 구조는 보존한다.**

## 0. 보호 토큰 — 절대 불가침

본문에 `⟦HZ-B0007⟧` `⟦HZ-I0023⟧` 형태의 토큰이 있다. 각각 코드블록·표·링크 주소·이미지·HTML·수식이 있던 자리다.

- 토큰은 **한 글자도 바꾸지 말고, 지우지 말고, 순서를 바꾸지 말고, 새로 만들지도 마라.**
- 토큰이 있던 자리를 문장으로 풀어 설명하지 마라. 그대로 두고 **주변 산문만** 손질한다.
- 블록 토큰은 자기 줄에 단독으로 있다. 그 줄은 그대로 통과시켜라.
- 토큰 개수·순서가 입력과 다르면 결과물은 **자동 폐기**된다. 윤문 전체가 버려진다.

## 1. 구조 보존 — 최상위 규칙

문서는 읽는 글이자 **찾는 글**이다. 구조를 바꾸면 목차·앵커 링크·독자의 탐색이 깨진다.

- **헤딩 줄(`#`~`######`)의 텍스트를 바꾸지 마라 — 이 지침 뒤에 이어지는 `## 이번 실행의 옵션 상태` 블록에서 "헤딩 편집: 꺼짐"이면(기본값).** 헤딩은 `#anchor` 링크의 대상이다. 문구가 어색해도 그대로 둔다. (바꿔도 자동 복구되므로 네 수정은 버려진다.)
  - **같은 블록이 "헤딩 편집: 켜짐"일 때만 예외.** 핵심 키워드·용어·번호("3장", "Phase 2" 등)는 보존한 채 콜론 부제 압축(C-10, §2 참고)과 상투어만 정리할 수 있다. 헤딩이 짧고 이미 깨끗하면 손대지 않는다(변경률 최소화 원칙). 같은 파일 내부 앵커의 `#anchor` 목적지는 별도 스크립트(`heading_anchor.py`)가 자동으로 갱신하니 네가 직접 손볼 필요는 없다. 다만 링크 텍스트는 이 스크립트가 건드리지 않으므로, 옛 헤딩 문구를 그대로 echo하고 있다면 통상적인 산문 정리 대상이다.
- **불릿·번호 목록을 산문으로 합치지 마라.** 항목 개수와 순서를 유지한다. 손질은 각 항목 **문장 내부**에서만.
- 문단을 쪼개거나 합치지 마라. 문단 개수를 유지한다(단, §8의 축약이 CONDENSE=1일 때 재진술 문장·문단을 지우는 것은 이 규칙의 문서화된 예외다 — 기본값이 CONDENSE=1이므로 기본적으로 적용된다).
- 표의 행·열 구조를 바꾸지 마라.

## 2. quick-rules 무효화 목록 — 이 문서에서는 적용하지 않는다

| 룰 | 원래 처방 | 문서에서는 |
|---|---|---|
| C-2 | 연속 불릿 → 산문 통합 | **적용 금지.** 목록은 문서의 자료구조다 |
| C-9 | "1) 2) 3)" → 산문에 녹임 | **적용 금지.** 순서 있는 절차다 |
| C-10 | 콜론 부제 헤딩 압축 | **옵션 켜짐 시에만 조건부 적용.** 핵심 키워드 보존, 콜론 부제 압축·상투어 제거만(§1 참고) |
| D-3 | "다음과 같은" 도입구 삭제 | **조건부.** 뒤에 실제 목록·코드블록·표가 오면 도입구를 남겨라. 뒤에 아무것도 없을 때만 삭제 |
| A-10 | "~할 수 있다" → 단언 | **보수적으로.** 기능 설명의 "~할 수 있다"는 실제 가능성 서술이다. 한 문단 3회+ 반복일 때만 손댄다 |
| I-4 | "~해야 한다" → 변주 | **보수적으로.** 절차 문서의 지시문은 그대로 두고, 논평·배경 문단에서만 변주 |
| E-1 | 문단마다 장문 1개 추가 | **약하게.** 참조형 문서는 짧은 게 미덕이다. 서술 문단에서만 적용 |

C-5(이모지)와 J-1(볼드)은 무효화가 아니라 **조건부 적용**이다 — 아래 §3에서 정확한 범위를 정한다.

## 3. 레이아웃 지문 제거 (L 계열) — 이 프로파일의 핵심

문장을 아무리 다듬어도 **문서 전체 레이아웃**이 그대로면 AI가 쓴 티가 난다.
`quick-rules.md`에는 이 축이 아예 없다. 기존 70패턴은 전부 문장·문단 단위다.

### 3-1. 제거한다

- **L1 볼드리드 불릿** — `- **성능**: 캐시 적중률이 올라간다` 형태가 3개 이상 연속되면 볼드 라벨을 걷어낸다.
  - 라벨이 뒤 문장과 의미가 겹치면 **라벨을 지우고 문장만** 남긴다 → `- 캐시 적중률이 올라간다`
  - 라벨이 고유 정보(옵션명·필드명·단계명·제품명)를 담고 있으면 **볼드만 풀고 텍스트는 보존** → `- 성능: 캐시 적중률이 올라간다`
  - **불릿 항목 자체를 없애거나 합치지는 않는다.** 개수는 그대로다.
- **L6 상태·장식 이모지** — ✅ ❌ ⚠️ 🚀 🔥 💡 📌 🎯 ✔️ ❗ 🎉 👉 ⭐ 등 헤딩 머리·불릿 머리·표 셀의 장식 이모지를 삭제한다.
  - 예외: 범례 표의 ✅/❌ 처럼 **이모지가 실제 값을 나르는 경우**는 보존.
- **L9 서두 요약 박스** — 첫 헤딩 직후의 `> **TL;DR**` / `**한 줄 요약**` / `**핵심**` 박스를 없앤다.
  - 그 내용이 본문에 이미 있으면 삭제. 없으면 **첫 문단에 평문으로 녹인다.** 내용을 버리지 마라.
- **L8 마무리 요약 섹션** — 마지막 "정리 / 요약 / 마치며 / 결론 / 핵심 정리" 섹션이 **본문의 순수 재진술**일 때만 삭제한다.
  - 새 정보(다음 단계, 남은 과제, 참고 링크, 실행 지시)가 한 줄이라도 있으면 **섹션을 남기고** 재진술 부분만 줄인다.
  - 판단이 서지 않으면 **남긴다.** 삭제는 되돌리기 어렵다.
- **L7 수평선 남발** — 섹션마다 붙은 `---`를 걷어낸다. 헤딩이 이미 경계다. 문서 전체에 1~2개는 남겨도 좋다.
- **L10 강조용 인용블록** — 실제 인용이 아닌데 강조하려고 쓴 `>` 블록은 평문 문단으로 되돌린다.
  - 출처·화자가 있는 진짜 인용, 그리고 경고·주의 박스는 보존.

### 3-2. 손대지 않는다 — 점수로 고지만 한다

표 밀도(L2), 섹션 골격 균질성(L3), 삼분 편향(L4), ASCII 도식(L5), 헤딩 깊이·형태 균일(L11·L14), 불릿 길이 균일(L12), 콜론 유도(L13).

구조를 바꿔야 고쳐지는 축이다. **자동 수정 금지.** 리포트로만 사용자에게 알린다.

### 3-3. 지문 재생산 금지 — 가장 중요하다

**너(윤문하는 모델)도 이 지문을 만드는 당사자다.** 걷어내면서 동시에 새로 심으면 아무 의미가 없다.

- 없던 **볼드리드 불릿**을 만들지 마라
- 없던 **이모지·체크마크**를 넣지 마라
- 없던 **요약 문단·마무리 정리**를 붙이지 마라
- 문단이나 항목을 **3개씩 짝맞추려** 하지 마라
- 없던 **`---` 수평선**을 넣지 마라
- 없던 **표**로 산문을 정리하지 마라

출력의 레이아웃 지문 점수는 `llm_signature.py`가 **윤문 전후로 기계 측정한다.** 점수가 오르면 결과물 전체가 폐기된다.

## 4. 문서에서 특히 강하게 잡을 문장 패턴

기술문서에서 유독 심한 AI 티다. 여기에 화력을 집중하라.

- **A-1 / A-3 / A-5 / A-11** 번역투 조사구("~에 대해", "~에 있어", "~와 관련하여", "~을 위해") — 문서에서 제일 흔하고 제일 거슬린다
- **A-7** "가지고 있다" / have 직역 — "이 기능은 ~한 장점을 가지고 있다" → "이 기능은 ~하다"
- **A-8 / A-9** 이중 피동, "~에 의해" — "설정에 의해 제어되어진다" → "설정이 제어한다"
- **A-15** 추상 주어 + 만능 동사 — "이 아키텍처는 유연성을 제공한다" → 실제 주체·구체 서술로
- **A-18 / A-19** 좌향 수식 장문, 이중 조사("~에서의") — 문서 가독성을 직접 깎는다
- **C-8** "A가 아니라 B다" 대구 — Claude가 문서당 5~10회 쓴다. 한 번만 남기고 평서문으로
- **D-1** 결산 lexicon("결론적으로", "이를 통해")
- **D-2** "시사하는 바가 크다 / 주목할 만하다" 의의 과장
- **F-4 / F-5** "-성 / -적 / -화" 명사화 누적 — 기술문서 번역투의 핵심
- **H-1 / H-3** 문두 접속사·메타 진입 남발
- **G-1 / G-2** "~로 보인다 / 판단된다" — 문서는 단언해야 한다

## 5. 용어 불가침 — Do-NOT 확장

quick-rules의 Do-NOT에 더해, 문서에서는 다음도 절대 건드리지 않는다. **백틱이 없어도** 마찬가지다.

- 명령어·플래그·경로·환경변수·파일명 (`kubectl get pods`, `--dry-run`, `/etc/hosts`, `NODE_ENV`)
- 제품·프로젝트·API·필드·리소스 이름 (Pod, Deployment, cgroup, throttling, CFS quota)
- 버전 번호·에러 코드·수치·단위
- 표준 기술 용어의 원어 (prompt, token, pipeline, rate limit) — 억지 번역 금지
- UI 문구·설정 키 이름·로그 메시지

## 6. register

기술문서의 기본은 평서 격식체(`~한다`/`~이다`) 또는 정중체(`~합니다`). **원문의 종결 스타일을 그대로 유지**하고, 한 문서 안에서 섞지 마라. 원문이 정중체면 결과도 정중체다.

## 7. 자체검증 추가 항목

quick-rules의 6항에 더해 다음 7항을 반드시 점검한다. 하나라도 위반이면 해당 edit 롤백.

7. 토큰 `⟦HZ-…⟧`이 입력과 출력에서 **개수·순서·표기가 완전히 동일**한가
8. 헤딩 줄이 한 글자도 바뀌지 않았는가(**헤딩 편집 옵션이 꺼져 있을 때만.** 옵션이 켜져 있으면 핵심 키워드·번호가 보존됐는지, 축약이 아니라 정리 수준인지만 확인한다)
9. 목록 항목 개수와 순서, 문단 개수가 그대로인가(축약이 꺼져 있을 때. 켜져 있으면 §8-2의 비대상을 지우지 않았는지로 대체한다)
10. 명령어·플래그·경로·식별자·설정 키가 그대로인가
11. **없던 이모지·볼드리드 불릿·`---`·요약 문단·표를 새로 심지 않았는가** (지문 재생산 금지)
12. L8·L9로 무언가를 삭제했다면, 그게 정말 재진술이었고 새 정보를 함께 버리지 않았는가
13. **축약(§8)으로 지운 내용이 정말 부차적이었는가(예시·반복)?** 유일한 근거·수치·핵심 주장을 지우지 않았는가

## 8. 축약(간결화) 기준 — 기본 켜짐

quick-rules 에는 이 개념이 아예 없다. 문장을 쪼개면(A-18 등) 전체 길이가 늘어나므로, 부차적인 내용은 판단해서 함께 줄인다. 이 지침 뒤에 이어지는 `## 이번 실행의 옵션 상태` 블록에서 "축약: 켜짐"이면(기본값) 아래 기준을 **항상 적용**한다. 같은 블록이 "축약: 꺼짐"일 때만(사용자가 `축약하지 마` / `원문 정보 그대로`라고 명시한 경우) 이 섹션 전체를 무시하고 원문 정보량을 그대로 유지하라.

### 8-1. 대상 — 축약 가능

| 유형 | 설명 |
|---|---|
| 재진술 | 이미 본문에 나온 내용을 다시 말한 문장·문단(요약 문단, 마무리 정리와 같은 성격이 문장 단위로 흩어진 경우 포함) |
| 예시 문장 | 핵심 주장을 뒷받침하려고 덧붙인 사례·일화. **단, 그 예시 안에 유일한 수치·근거가 있으면 대상에서 제외**(§8-2) |
| 중복 표현 | 같은 내용을 다른 표현으로 두 번 이상 말한 경우 — 한 번만 남긴다 |
| 과잉 부연 | 이미 명확한 문장 뒤에 같은 뜻을 다시 설명하는 절 |

### 8-2. 비대상 — 불가침(기존 원칙과 동일)

- 사실, 수치, 날짜, 고유명사
- 핵심 주장·결론 자체
- 절차 문서의 단계·순서
- **유일하게 등장하는 근거** — 그 문장을 빼면 주장이 근거 없이 남는 경우. 예시 문장이라도 이 조건에 해당하면 비대상이다

### 8-3. 판단이 애매하면

**남긴다.** L8(마무리 요약 섹션, §3-1)의 "판단이 서지 않으면 남긴다. 삭제는 되돌리기 어렵다" 원칙을 그대로 승계한다.

### 8-4. 게이트

새 게이트를 만들지 않는다. 삭제로 늘어난 변경률은 게이트 B(`verify_gates.py`)가 그대로 잡는다(경고 시 후속은 SKILL.md의 게이트 B 절이 정한다). §7의 13번 항목이 이 기준의 자체검증을 담당한다.
