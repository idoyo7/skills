# 한국어 문장의 의미 관계를 명확하게 쓰기

한국어 산문을 편집할 때 적용한다. 번역투·반복 표현을 줄이면서도 누가 무엇을 하는지, 어떤 조건에서 성립하는지가 드러나게 쓴다. 짧은 문장이나 금지어 감소 자체를 목표로 삼지 않는다.

## 적용 범위와 우선순위

사용자가 정한 편집 범위와 원문의 사실·수치·조건·주장 강도 보존을 먼저 지킨다. 보존 윤문에서는 보호 토큰과 구조 제약을 그대로 따르고, 구조 재작성에서도 문장을 명확하게 한다는 이유로 근거를 추가하지 않는다. 검사만 요청했다면 발견 사항만 보고한다.

코드·코드 주석·명령어·설정 키·경로·로그·직접 인용은 교정하지 않는다. 마스킹된 토큰을 풀어 설명하거나 그 안의 내용을 추측하지 않는다. 원문에서 사용하는 제품명·기술 용어·식별자는 유지하며, 문법을 고친다는 이유로 번역하거나 다른 어휘로 치환하지 않는다. 원문의 종결 문체와 사용자가 지정한 문체를 따른다.

`quick-rules`의 압축·명사화 축소·리듬 변주 처방으로 의미 관계가 흐려지면 이 지침에 따라 문장을 풀어 쓴다. 한자어 자체는 제거 대상이 아니다. 의미를 전달하는 어휘를 보존하면서 조사·어미와 서술어를 고친다. 아래 엠대시 기준은 편집 가능한 산문에서 관계가 모호한 경우에 한해 J-3와 monolith의 원문 대시 보존 처방보다 우선한다. 명확한 부가설명 대시는 보존한다. 인용과 보호 대상에는 적용하지 않는다.

시드(`author-tics.txt`) 지침이 "다만"·"반면"·"실은"·"동시에" 같은 접속사를 습관 표현으로 지목해 생략·분할을 지시하더라도, 그 접속사가 실제 대조·조건·인과 관계를 나타내는 자리라면 이 지침에 따라 관계를 살려 쓰고 시드 처방은 습관적으로 반복된 경우에만 적용한다.

## 문장을 고칠 때

1. **문맥으로 확인되는 문장 성분을 살린다.** 주체·대상·조건이 빠져 뜻이 달라질 수 있으면 원문에서 확인한 정보로 명시한다. 앞 문장만으로 분명한 주어를 매번 되풀이할 필요는 없다. 원문 전체에도 없는 주체나 인과관계는 만들어 넣지 말고, 모호한 구간을 보고한다.

   원문: “배포 도구는 변경된 설정 파일을 검사한다. 검사 실패 시 배포 중단.”
   편집: “배포 도구는 변경된 설정 파일을 검사한다. 검사에 실패하면 배포를 중단한다.”
   “그러면 경고가 표시된다”만 있고 경고의 위치가 어디에도 없다면, “설정 화면에”를 임의로 덧붙이지 않는다.

2. **명사 나열을 조사·어미로 연결한다.** `~의`를 반복하거나 명사를 붙여 관계를 압축하지 않는다. 기존 용어를 유지하면서 무엇의 조건·원인·대상인지 드러내고, 부사나 보조 용언은 실제 시점·범위·태도를 나타낼 때 쓴다. 단어 수를 맞추려고 장식적인 말을 늘리지 않는다.

   원문: “요청 처리 지연 원인 확인 후 제한값 조정 필요.”
   편집: “요청 처리가 지연되는 원인을 확인한 뒤 제한값을 조정해야 한다.”
   “캐시 적중률”, “가비지 컬렉션”처럼 정착된 기술 용어를 문법 교정 대상으로 분해하지 않는다.

3. **본문 문장은 서술어와 종결어미로 끝낸다.** 명사구·부사구·연결어미로 끝난 문장은 원문의 의미와 문체에 맞게 완성한다. 제목·표의 셀·목록의 짧은 항목은 문장형으로 강제하지 않는다. 목록 안에서 설명 문장으로 쓰인 부분은 뜻이 명확하도록 다듬되 항목 수와 순서 등 현재 모드의 제약을 지킨다.

   본문 “이 설정은 재시도 횟수의 상한.” → “이 설정은 재시도 횟수의 상한이다.”
   제목 “재시도 횟수”와 목록 항목 “기본값: 3회”는 그대로 둘 수 있다.

4. **비유가 가리는 동작을 직접 쓴다.** “설정에 박아 넣는다”, “검증을 얹는다”처럼 실제 동작 대신 쓴 비유는 문맥에서 확인되는 동사로 고친다. 특정 단어를 금지하거나 다른 비유로 돌려 쓰지 않는다. 해당 분야에서 통용되는 “트래픽 병목”, “파이프라인”이나 의도된 문학적 표현은 기계적으로 바꾸지 않는다. 의미를 보존하는 대체가 불확실하면 원문을 남긴다.

   “재시도 횟수는 설정 파일에 박아 넣는다.” → “재시도 횟수는 설정 파일에 명시한다.”

5. **엠대시가 감춘 관계를 풀어 쓴다.** 원인·조건·부연을 `—` 하나로 연결해 뜻이 모호해지면 그 관계에 맞는 접속사·괄호·콜론이나 완결된 문장으로 바꾼다. 관계가 확인되지 않는데 “따라서”, “때문에”를 넣지 않는다. 명확한 삽입구는 유지할 수 있으며, 엠대시 개수 0을 목표로 삼지 않는다.

   “응답이 없으면 요청을 다시 보낸다 — 최대 3회.” → “응답이 없으면 요청을 최대 3회 다시 보낸다.”

## 편집 뒤 대조

바뀐 문장을 원문과 나란히 읽으며 주체·대상·조건·수치의 관계와 가능성·의무·추정이 같은지 확인한다. 예를 들어 “512Mi에 overhead 600Mi를 더해야 한다”를 “512Mi와 overhead 600Mi가 필요하다”로 바꾸면 가산 관계가 사라진다. 조사만 바뀌어도 해당 주장 전체를 대조한다.

필요한 조사·어미를 복원해 문장이 길어진 것은 그 자체로 과잉 부연이 아니다. 다만 기존 보존 게이트와 사용자의 콜·비용 한도는 그대로 적용한다. 새 지침을 이유로 게이트를 건너뛰거나 추가 편집 콜을 만들지 않는다. 이미 수행하는 윤문·자체검증·내용 검증 안에서 확인한다. L1~L14와 S1~S3 점수는 이 문장 검토를 대신하지 않는다. S4(명사형·연결어미 종결) 건수도 마찬가지로 정규식 근사의 참고 수치일 뿐이라 오르내림만 보고 문장 검토를 생략하지 않는다.
