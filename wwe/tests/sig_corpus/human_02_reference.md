# 사내 배치 스크립트 레퍼런스

크론에 등록된 배치 스크립트 목록과 각각의 대략적인 실행 시간, 담당(이었던) 팀을 정리해둔다.
새로 합류한 사람은 일단 이 문서부터 보고, 애매하면 #data-platform 채널에 물어보면 된다.

## 정리/청소 계열

이 계열은 대부분 디스크나 로그 관리용이라 실패해도 당장 큰일은 안 난다. 다만 오래 방치하면
디스크가 꽉 차서 다른 작업까지 실패할 수 있으니 월 1회 정도는 훑어보는 게 좋다.

| 스크립트 | 주기 | 실행 시간 | 비고 |
|---|---|---|---|
| clean-tmp.sh | 매일 03:00 | 2분 미만 | /tmp 7일 이상 파일 삭제 |
| rotate-app-logs.sh | 매일 04:00 | 5분 내외 | logrotate 래퍼, 설정은 /etc/logrotate.d/app |
| archive-old-jobs.sh | 매주 일요일 | 20~40분 | 6개월 지난 배치 결과물 S3로 이관. 실행 시간 편차 큼 |

## 데이터 집계

여기부터는 실제로 뭔가 계산하는 스크립트들이라 실패하면 대시보드가 하루 밀린다.

| 스크립트 | 주기 | 실행 시간 |
|---|---|---|
| daily-revenue-rollup.py | 매일 01:00 | 15분 |
| weekly-cohort.py | 매주 월요일 06:00 | 1시간~1시간 20분 |

daily-revenue-rollup은 2024년쯤 Airflow로 옮겨졌다는 얘기를 들었는데, 확인해보니 크론에도
여전히 남아 있다. 둘 다 살아있는 건지 하나가 죽은 잔재인지는 이 문서 쓰는 시점 기준으로
확인 못 했다. 누가 알면 여기 적어주길 바란다.

## 알림/모니터링

- disk-usage-alert.sh — 매시간, 디스크 85% 넘으면 Slack 알림. 임계값은 스크립트 안에
  하드코딩돼 있어서 바꾸려면 직접 수정하고 재배포해야 한다
- cert-expiry-check.sh — 매일, 인증서 만료 30일 전부터 경고. 이거 덕분에 작년에 있었던
  인증서 만료 사고는 안 일어났다
- oncall-heartbeat.sh — 5분마다, 그냥 살아있다는 신호만 보냄. 이게 안 오면 서버가 죽은 거다

## 알아두면 좋은 것들

담당자가 바뀌거나 퇴사하면서 주석이 사라진 스크립트가 꽤 있다. `git blame`을 걸어봐도
커밋 메시지가 "fix"나 "update" 한 줄뿐인 경우가 태반이라 크게 도움이 안 될 때가 많다.
실행 시간이 이상하게 튀는 스크립트가 있으면 대체로 외부 API 호출 부분에서 타임아웃이
길게 잡혀 있는 게 원인인 경우가 많았다. archive-old-jobs.sh가 특히 그렇다.

크론탭 원본은 `/etc/cron.d/batch-jobs`에 있고, 이 표에 없는 항목을 발견하면 일단
`crontab -l -u batch`로 실행 이력부터 확인해보는 걸 권한다.
