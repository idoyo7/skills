# nginx keepalive 튜닝하다 겪은 일

지난주에 백엔드 응답 시간이 가끔 1초 넘게 튀는 문제가 있어서 들여다봤다. 결론부터
말하면 nginx와 upstream 사이 커넥션이 매번 새로 맺어지고 있었던 게 원인이었다.

## 발견 과정

처음엔 애플리케이션 쪽 GC 문제인 줄 알고 힙 덤프까지 떴는데 별 이상이 없었다.
tcpdump로 한참 들여다보다가 upstream으로 가는 연결이 요청마다 3-way handshake를
새로 하고 있다는 걸 알아챘다. nginx 설정을 보니 upstream 블록에 keepalive
지시어가 아예 빠져 있었다.

## 설정 변경

바꾼 부분은 다음과 같다.

- upstream 블록에 `keepalive 32;` 추가
- proxy_http_version을 1.1로 올림 (keepalive는 1.0에서 안 됨)
- proxy_set_header Connection ""로 비워줌

## 결과

변경 전에는 p99가 1.2초 언저리였고, connection reuse 관련 카운터도 거의 0에
가까웠다. 변경하고 나서 하루 지켜본 결과 p99가 180ms 정도로 떨어졌다. upstream
쪽 CPU 사용량도 소폭 줄었는데 이건 handshake 자체가 생각보다 비용이 크다는
뜻인 것 같다.

다만 keepalive 커넥션 수를 너무 크게 잡으면 upstream 쪽에서 유휴 연결을 계속
쥐고 있어야 해서, 32라는 숫자는 우리 트래픽 패턴 기준으로 대충 맞춘 값이지
일반화된 권장값은 아니다. 트래픽 늘어나면 다시 봐야 할 것 같다.
