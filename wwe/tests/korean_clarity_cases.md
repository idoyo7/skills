# 한국어 명확성 지침의 행동 검증 사례

공통 지침과 해당 편집 경로를 읽은 평가자에게 요청·입력만 제공하고 후보와 검토 메모를 받는다. 아래 확인 기준은 후보를 받은 뒤 원문과 대조하는 데 사용한다. 정답 문구 일치 테스트나 자동 문법 검사로 취급하지 않는다. 기존 `run.sh`에는 포함되지 않으며, 결과는 실제 사용한 모델과 편집 범위에 한정한다.

## 1. 문장만 편집

요청: “제목·목록·문단 구조와 정보는 그대로 두고 문장만 다듬어줘.”

입력:

```markdown
# 재시도 설정

클라이언트는 서버 응답을 기다린다. 응답 없으면 요청 재전송 필요. 재시도 횟수는 설정 파일에 박아 넣는다 — 최대 3회.

이 설정은 재시도 횟수의 상한.

- 기본값: 3회
- 설정 키: retry_count
```

확인 기준: 주체와 조건을 원문에서 복원하고 본문을 완결된 문장으로 쓴다. 의무를 가능성으로 약화하지 않으며 `3회`의 상한 관계를 유지한다. 비유 대신 동작을 직접 쓰고 제목·문단 경계·목록 수와 순서를 보존한다. 짧은 목록 항목은 억지로 문장형으로 바꾸지 않는다.

## 2. 코드·인용·수치 관계

요청: “문장만 다듬어줘. 코드와 인용은 그대로 둬.”

입력:

````markdown
# 메모리 설정

Pod 요청량 512Mi에 overhead 600Mi 더해야 한다. 이 값이 실제 사용량보다 클 수 있다.

캐시 적중률은 그대로다. 설정값은 `retry_count`에 박아 넣는다.

> 운영자는 "응답 없음 — 원인 불명"이라고 기록했다.

```python
# 응답 없음 — 원인 불명
retry_count = 3
```
````

확인 기준: `512Mi`와 `600Mi`의 가산 관계, “더해야 한다”의 의무, “클 수 있다”의 가능성을 보존한다. Pod·overhead·캐시 적중률·retry_count를 번역하거나 다른 개념으로 바꾸지 않는다. 직접 인용과 코드 주석 안의 생략·엠대시는 그대로 둔다.

## 3. 문맥에 없는 정보와 통용되는 비유

요청: “문장만 다듬고, 의미를 확정하기 어려운 곳은 별도로 알려줘.”

입력:

```markdown
# 관측 기록

그러면 경고가 표시된다. 이후 처리 지연.

트래픽 병목은 네트워크에서 발생했다. 파이프라인은 세 단계로 구성되어 있다.
```

확인 기준: 경고의 조건·위치나 지연의 원인을 만들어 넣지 않는다. 원문만으로 확정할 수 없는 관계를 검토 메모에 남긴다. “트래픽 병목”과 “파이프라인”을 금지어처럼 교체하지 않는다.

## 4. 검사 범위

사례 1의 입력으로 “지문 점수만 계산해줘”와 “한국어 문장 문제만 검토해줘. 수정하지 마”를 각각 요청한다. 전자는 요청한 자동 지표만 계산하며 문장 검토나 후보 생성을 추가하지 않는다. 후자는 발견 사항만 보고하고 본문을 수정하지 않는다. 문장 점검이 자동 점수에 포함된다고 주장하지 않는다.
