# 캐시 무효화 전략 노트

캐시 무효화는 배포 시스템에서 가장 다루기 어려운 문제 중 하나로 꼽힌다. 아래에서 세 가지
접근 방식을 정리한다.

## TTL 기반 만료

TTL 기반 만료는 캐시 항목에 유효 기간을 설정해 자동으로 제거하는 방식이다.

- **설정 단순성**: 항목마다 만료 시간만 지정하면 되므로 구현이 간단하다
- **일관성 지연**: 만료 시점까지는 오래된 데이터가 노출될 수 있다
- **운영 부담 낮음**: 별도의 무효화 로직을 관리할 필요가 없다

세 가지 특성 모두 트레이드오프를 수반하므로 서비스 요구사항에 맞춰 TTL 값을 조정해야 한다.

## 이벤트 기반 무효화

이벤트 기반 무효화는 데이터 변경 시점에 맞춰 캐시를 즉시 제거하는 방식이다.

- **즉시 일관성**: 데이터가 바뀌면 캐시도 바로 갱신된다
- **구현 복잡도**: 모든 변경 경로에 무효화 로직을 삽입해야 한다
- **장애 전파 위험**: 무효화 이벤트 유실 시 오래된 데이터가 계속 노출된다

세 가지 특성은 TTL 방식과 정확히 대칭을 이루는 트레이드오프를 보여준다.

## 버전 태깅

버전 태깅은 캐시 키에 데이터 버전을 포함시켜 자동으로 새 키를 생성하는 방식이다.

- **무효화 불필요**: 버전이 바뀌면 새 키가 생성되므로 명시적 삭제가 필요 없다
- **저장 공간 증가**: 오래된 버전의 캐시 항목이 자동으로 정리되지 않으면 쌓인다
- **키 설계 부담**: 버전 정보를 포함한 키 체계를 미리 설계해야 한다

세 가지 방식 모두 나름의 장단점이 있으며, 실무에서는 종종 혼합해서 사용한다.

## 선택 기준

전략을 고를 때 고려할 세 가지 요소는 다음과 같다.

- **데이터 변경 빈도**: 자주 바뀌는 데이터는 이벤트 기반이 유리하다
- **일관성 요구 수준**: 강한 일관성이 필요하면 이벤트 기반을 우선한다
- **팀의 운영 역량**: 무효화 로직 관리 여력이 부족하면 TTL이 안전하다
