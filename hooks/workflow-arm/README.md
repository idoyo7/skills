# workflow-arm

Claude Code PreToolUse 훅. `Workflow` 툴을 실제로 실행하려는 호출을 가로채, 이 cwd에 대한 재개 예약(freeze arm)이 걸려 있는지 확인하고 없으면 먼저 예약부터 걸라고 한 번 막는다.

## 왜 필요한가

큰 워크플로우는 수십만 토큰을 태울 수 있고, 도중에 5시간 사용량 한도에 걸리면 handoff를 남길 토큰조차 없이 그냥 끊길 수 있다. freeze 스킬의 `arm` 모드는 작업을 시작하기 전에 미리 예약을 걸어두고, 한도에 막히는 순간 예약이 이어받게 한다. 이 훅은 그 순서를 강제한다 — 예약 없이 Workflow를 부르면 일단 막는다.

## 판별 로직

**대상 호출만 본다.** `tool_name`이 `Workflow`가 아니면 통과. `tool_input`에 `script`, `scriptPath`, `name` 중 아무것도 없으면(즉 `runId`만 있는 조회·제어 호출이면) 통과한다.

**작은 워크플로우는 규모 판정에서 바로 통과한다.** 이 훅은 script/scriptPath/name이 있다고 무조건 막지 않는다. 먼저 서브에이전트 개수를 추정해 임계값(기본 10, `FREEZE_HOOK_AGENT_THRESHOLD`로 오버라이드) 이하면 예약 여부조차 확인하지 않고 통과시키고, 세션 마커도 남기지 않는다 — 작은 워크플로우 한 번이 그 세션의 "한 번만 막기" 기회를 태워버리면 안 되기 때문이다. 규모 판정이 활성 예약 확인보다 먼저 일어나는 이유가 이것이다.

스크립트 텍스트는 `script`가 있으면 그대로, `scriptPath`가 있으면 그 경로를 읽어서, `name`이 있으면 cwd 기준 `.claude/workflows/<name>.{js,mjs,ts}`를 찾고 없으면 `~/.claude/workflows/`에서 찾아서 얻는다. 어느 쪽이든 텍스트를 얻지 못하면(파일이 없거나 읽기 실패) 판정 없이 그대로 통과한다 — 예상 밖 상황에서는 절대 막지 않는다는 이 훅의 원칙 그대로다.

**패턴 매칭 전에 주석·정규식 리터럴·문자열을 지운다.** `//`, `/* */` 주석, JS 정규식 리터럴(`/.../ flags`), `'`/`"`/백틱 문자열 리터럴은 같은 길이(위치 보존)로 미리 지운 텍스트 위에서만 정규식·배열 판정이 돈다. 주석에 적어둔 `for (` 예시나 문자열 속 `.map(`이라는 글자 때문에 작은 워크플로우가 잘못 막히는 일을 막기 위해서다. 정규식 리터럴은 문자열보다 먼저 처리하는데, 안 그러면 정규식 안의 따옴표(`/['"]/`)를 문자열 여는 따옴표로 오인해 다음 따옴표(또는 파일 끝)까지 통째로 지워버려 뒤따르는 `agent(`·`.map(`·배열 리터럴이 전부 사라진다 — 큰 워크플로우가 작다고 오판되는 가장 위험한 방향이다. 정규식 시작 여부는 "나눗셈 vs 정규식"을 가르는 고전적 휴리스틱으로 판별한다: `/` 직전의 비공백 문자가 `)`·`]`·`}`·식별자 문자·숫자가 아니면 정규식 시작으로 본다. 이스케이프(`\/`)와 문자 클래스(`[...]` 안의 `/`)를 존중해 닫는 `/`를 찾고, 줄바꿈 전에 못 닫으면(JS 정규식 리터럴은 한 줄을 못 넘는다) 정규식이 아니라고 보고 원래 문자로 되돌린다.

추정은 `agent(` 호출 개수에서 시작하지만, `parallel(`/`pipeline(`는 Workflow 툴의 표준 API라 대부분의 스크립트가 쓰므로 이 둘을 발견 즉시 무조건 막지는 않는다. `parallel(`/`pipeline(`/`.map(`/`.forEach(`/`.flatMap(`을 만나면 그 팬아웃 "대상"의 크기를 정적으로 셀 수 있는지부터 본다 — 인라인 배열 리터럴(`[...].map(...)`, `pipeline([...], ...)`)이거나 `const`/`let`/`var`로 선언된 배열 식별자(`const DIMENSIONS = [...]; pipeline(DIMENSIONS, ...)`)면 그 원소 개수를 곱셈 계수로 쓴다. 배열 크기는 문자열·중첩 배열·객체 안의 콤마·괄호까지 깊이를 세어 정확히 판정한다(`[[1,2],[3,4]]` → 2, `["a,b","c"]` → 2). 다만 배열 리터럴 안에 spread(`[...items]`, `[...Array(100)]`)가 섞여 있으면 진짜 크기를 알 수 없으므로 아예 크기를 셀 수 없는 배열로 취급한다. 이름으로 참조하는 배열도 마찬가지로 못 믿을 신호가 있으면 크기를 모르는 것으로 강등한다 — 같은 이름이 두 번 이상 선언되거나(이 스캐너는 스코프를 구분하지 않으므로 다른 함수 안의 동명 지역 변수까지 포함), 선언 뒤 재대입(`tasks = ...`)되거나 `.push(`/`.concat(`/`.splice(`/`.unshift(`로 변형되면 선언 시점 크기를 더 이상 안 믿는다. 속성 접근(`review.findings.map(...)`)이나 함수 호출 결과(`getItems().map(...)`) 위를 도는 팬아웃, `for (`/`for await`/`while (` 루프, 그리고 이 파일이 아는 팬아웃 마커 다섯 개(`parallel`/`pipeline`/`.map`/`.forEach`/`.flatMap`) 밖에서 벌어지는 팬아웃 — `Array.from(`/`new Array(`/`.fill(`/`.reduce(`/`Promise.all(`/`Promise.allSettled(` — 는 반복·원소 개수를 정적으로 알 수 없으므로 무조건 막는다. `agent`라는 단어가 `agent(` 호출 형태보다 더 많이 나오는 경우(`specs.map(agent)`처럼 함수 참조만 point-free로 넘기는 형태)도 그만큼을 못 세는 것이므로 무조건 막는다 — 셀 수 없는 쪽이 정확히 위험한 쪽이라서 보수적으로 간다.

**팬아웃이 중첩되면 곱한다.** 한 팬아웃의 콜백 안에 또 다른 팬아웃이 있으면(예: 10개짜리 배열 위 `pipeline` 안에 또 10개짜리 배열 위 `pipeline`이 있으면) 두 크기를 곱해 100으로 추정한다 — 여러 팬아웃 크기를 `max()` 하나로 접으면 실제보다 작게 잡혀 큰 워크플로우가 통과해버리는 사고로 이어진다. 단, `parallel(X.map(...))`처럼 바깥 호출의 유일한 인자가 안쪽 팬아웃 표현식 그 자체를 그대로 넘기기만 하는 pass-through는 곱하지 않는다 — 안쪽 `.map(`이 이미 별도 팬아웃 사이트로 잡혀 자기 크기(X의 원소 수)만큼만 반영하므로, 바깥 호출까지 곱하면 중복 계산이 된다. 앞뒤에 다른 연산이 섞이면(`foo + X.map(...)`, `X.map(...).filter(...)`) pass-through로 보지 않고 크기를 알 수 없는 쪽으로 떨어진다.

모든 팬아웃 대상을 셀 수 있으면 추정치는 `agent( 개수 × max(전체 팬아웃 배수, 1)`이다. deny 사유 맨 앞에는 "서브에이전트 N개로 추정된다(임계값 10)" 또는 "팬아웃 대상 크기를 정적으로 셀 수 없다" 한 줄이 붙는다.

**활성 예약이 있으면 통과.** (여기서부터는 규모 판정을 통과하지 못한, 즉 큰 워크플로우에만 적용된다.) `$FREEZE_STATE_DIR`(기본 `~/.local/state/freeze`) 아래 각 잡의 `reservation.json`을 읽어 `cwd`가 이번 호출의 cwd와 일치하고 `status`가 종료 상태(`cancelled`, `completed_early`, `probe_failed`, `done`, `failed`)가 아닌 것이 하나라도 있으면 막지 않는다. 상태값은 freeze.sh/thaw.sh가 실제로 쓰는 값을 그대로 따른다.

**세션당 한 번만 막는다.** 예약이 없으면 막되, 같은 세션에서 이미 한 번 막은 적이 있으면 두 번째부터는 통과시킨다. 세션 마커는 `$FREEZE_STATE_DIR/workflow-arm-sessions/<session_id>` 파일로 남기고, 7일 지난 마커는 다음 호출 때 정리한다.

**상태 디렉토리가 없으면 "예약 없음"으로 다뤄 막는다.** freeze를 한 번도 안 쓴 환경이 바로 이 훅이 막아야 할 대상이므로, 부재를 통과로 처리하면 첫 사용자에게는 이 가드가 영원히 발동하지 않는다. 부재 시 훅이 마커 디렉토리를 만드는 과정(`marker_dir.mkdir(parents=True, ...)`)에서 상태 디렉토리 자체도 함께 생성된다.

**그 외 예상 밖 상황에서는 절대 막지 않는다.** 상태 디렉토리는 있는데 읽을 수 없거나(권한, 읽기 전용 마운트), stdin JSON이 깨졌거나, 세션 마커를 쓸 수 없는 등 부재가 아닌 오류 상황에서는 조용히 통과한다. 훅 때문에 작업이 영구히 멈추는 것이 가장 나쁜 실패다.

## deny 출력 계약

```json
{
  "hookSpecificOutput": {
    "hookEventName": "PreToolUse",
    "permissionDecision": "deny",
    "permissionDecisionReason": "..."
  }
}
```

`permissionDecisionReason`에는 원장 작성(`wfledger.sh init`) → 예약(`freeze.sh arm --mode ledger`) → Workflow 재호출 순서를 실제 cwd를 채운 명령줄과 함께 담는다. 2번 명령은 `--at`을 안 주면 기본값 `auto`로 땡 시각을 추정하는데, 리셋 경계 등에서 추정이 실패(`UNKNOWN`)하면 exit 1 하고 예약이 하나도 안 걸린다 — 사유에는 이때 `--at HH:MM`으로 직접 지정하라는 안내를 함께 담는다. 이 가드를 아예 끄는 법(`FREEZE_HOOK_OFF=1`)도 사유 끝에 적는다.

**세션당 한 번만 막는 계약과 arm 실패가 겹치는 경우.** 2번이 실패해 예약이 안 걸린 채로 Workflow를 다시 부르면, 이 세션은 이미 마커를 찍어놨으므로 두 번째 호출은(위 "세션당 한 번만 막는다") 그대로 통과한다 — 훅은 그 사이의 `freeze.sh arm` 실행 결과를 볼 수 없어 절차가 끝난 뒤에 마커를 찍을 방법이 없기 때문이다. 대신 통과시키는 그 순간 마커에 "이 cwd는 예약 없이 통과됐다"는 사실을 남겨두고, 다음에 같은 cwd가 새 세션에서 처음 막힐 때 사유 맨 앞에 경고 한 줄을 보탠다.

## 끄는 법

전역 킬스위치 `DISABLE_OMC`나 이 훅 전용 `FREEZE_HOOK_OFF=1` 환경변수를 세팅하면 즉시 통과한다. `install.sh --no-hooks`로 설치하면 애초에 등록되지 않는다.

## 설치

저장소 루트에서 `install.sh`를 실행하면 다른 훅들과 함께 심링크와 `settings.json` 등록을 자동으로 처리한다.

```bash
cd <저장소 루트>
bash install.sh
```
