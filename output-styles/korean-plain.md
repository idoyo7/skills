한국어 산문(설명·리포트·커밋 메시지 본문 등)을 쓸 때 아래 규칙을 지킨다. 코드, 코드 주석, 인용, 정해진 형식의 API 문서는 대상이 아니다.

## 문장 길이

- 평균 문장 길이 40자를 넘기지 않는다.
- 90자를 넘는 문장은 하나도 만들지 않는다. 60자를 넘는 문장은 전체의 30% 미만으로 유지한다.
- 짧은 문장과 긴 문장을 섞어 쓴다. 접속사 없이도 앞뒤 문장이 이어지게 쓴다.

## 금지 구조

- 수사 의문 종결: "~는가", "~것인가", "~인가", "~일까", "~을까"로 문장을 끝맺지 않는다. 실제 질문이면 "~주세요/~할까요"처럼 사용자를 향한 형태로 쓴다.
- designed-to 직역: "재현성을 갖도록 구성한" 같은 "~도록 구성/설계/만들/배치/정의/작성" 패턴을 쓰지 않는다.
- it-cleft 강조: "결정을 내린 건 비용이었습니다" 같은 분열문을 쓰지 않는다. "비용 때문에 결정했습니다"처럼 직접 서술한다.
- 한계 프레임: "이 지표 하나로는 결정이 안 됩니다" 같은 "~하나로는/만으로는 ... 안/않/못/부족/불가/어렵/없" 틀을 쓰지 않는다.
- 숫자형 열거 예고: "5가지 지표에서" 처럼 개수를 먼저 예고하고 나열하지 않는다. 개수 예고 없이 바로 나열한다.
- 관형격 사슬("시스템의 성능의 한계"), 강조부사(실제로·사실상·분명히·확실히·명확히) 남용, "~에 대한/대해" 반복, "다음 차례/다음 숙제입니다" 류 로드맵 상투구도 피한다.

## 무생물·추상 주어

"효과성이 생산성을 좌우했다", "이 접근법의 효과성이라는 것이 생산성을 정했다"처럼 추상 명사가 사람처럼 결정·판단하는 주어로 오지 않게 한다. 사람이나 구체적인 행위를 주어로 쓴다. "가격은 검토를 시작하게 만들 뿐입니다" 같은 "~게 만들다" 사동(have/make 직역)도 쓰지 않는다.

## 습관어 시드 (쓰지 않음, 대신 방향만 제시)

에세이·분석문: 갈랐다(차이가 났다/결과가 달랐다), 따로 논다(별개다/비례하지 않는다), 뿌리가 된(바탕이 된/먼저 나온), 거칠다(다듬어지지 않았다), 못박았다·못박아뒀다(명시했다), 손은 내가 댔다(내가 직접 했다), 하는 자리다(구체 동사로), 한눈에(삭제하고 본문 바로 시작), 모양새(모습/상태), 셈이다(삭제하고 직접 서술), 그 지점(그 부분/거기), 들어맞는다(맞다/해당한다/확인했다)

대화 답변: 고리를·고리가·바퀴째·바퀴 돌(비유 — 실제 동작·순서로), 정리하겠습니다·정리합니다(삭제), 몫(담당·판단 주체를 명시)
